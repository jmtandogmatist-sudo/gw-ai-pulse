# V3.2 编辑判断方法

判断层只能使用本期已通过 G1 的事实，不得新增事实、数字或来源。先冻结事实层，再做判断。无适用透镜时使用 `N/A`，不要硬贴。

## 1. 四透镜

| 透镜 | 适用条件 | 必要证据 | 反例/不适用 | 输出要求 |
|---|---|---|---|---|
| 【价值层移动】 | 事件明确改变模型、基础设施、分发或应用层的价值获取、议价权或生态位置 | 产品/商业动作的官方材料 + 至少一个独立来源；能指出“从哪层到哪层” | 单纯版本更新、性能自报、没有商业或生态变化 | 说明价值捕获层变化；证据不足选 `N/A` |
| 【部署边界】 | 事件直接涉及托管/自有、云/端、数据或代码出域、权限与隔离 | 部署架构、数据流、许可或安全边界的一手说明 | 只说“企业级”“安全”但无边界细节 | 明确边界变化，不推断内部部署选择 |
| 【能力阈值】 | 能力升级同时改变可用性、可靠性、安全限制或访问门槛 | 版本能力、评测口径及限制条件；厂商自报需标注 | 只有宣传口号或孤立 benchmark | 同时写能力与限制；不可只放大性能 |
| 【业务距离】 | 事件有可证明的能源/风电直接应用，或迁移链条短且证据充分 | 能源场景案例、研究或工程条件；能描述迁移所需环节 | 泛化地声称“可赋能风电”、缺内部数据、迁移链过长 | 仅描述距离与迁移条件；不输出“对金风的启示” |

**V4.1 起正文不再输出透镜标签**：上表四个透镜降为写作时的内部分析框架，用于确认「这条到底改变了什么」，不出现在日报正文；
正文改用行动标签【需行动】【可借鉴】【了解】（写在 `###` 标题里，判定读者该做什么），并在「**对我们：**」行给出判断。
一条新闻最多对应一个透镜、一个行动标签，不得叠加，不得自创第五种。

## 2. 编辑部排序与当日论点

- 排序：从已验证今日大事件中选 1 条最重要、1-2 条次要，并仅用已验证事实说明理由。
- 确定事实优先于传闻、意向、未签署交易或单方预测。
- 当日论点：只有至少两条独立事件共同支持一个可证伪判断时才写；否则省略。
- 所有判断显式标注【编辑判断】；判断内容与事实内容分离。
- 修改事实层后重新评估排序、论点和透镜，不机械沿用。

## 3. 事件日程台账

用途：跟踪未来可观察事件，不评价编辑判断是否正确。建议保存在 `判断台账.json` 的 `events` 区域。

```json
{
  "event_id": "2026-09-03-event-slug",
  "introduced_issue": "AI-RADAR-2026-09-03",
  "subject": "未来事项",
  "due_date": "YYYY-MM-DD 或 null",
  "expected_signal": "可观察结果",
  "evidence_requirements": ["需要何种来源确认"],
  "status": "pending|hit|missed|cancelled",
  "resolved_issue": null,
  "resolution_receipts": [],
  "note": ""
}
```

状态只由可观察事件决定：发生且证据通过为 `hit`；到期未发生为 `missed`；未到期为 `pending`。不得把“编辑判断看起来合理”写成事件命中。

## 4. 编辑判断验证台账

用途：后验检验排序、论点和透镜，不与事件日程混用。建议保存为 `judgments` 区域。

```json
{
  "judgment_id": "J-2026-09-03-01",
  "introduced_issue": "AI-RADAR-2026-09-03",
  "statement": "可证伪的编辑判断",
  "lens": "价值层移动|部署边界|能力阈值|业务距离|N/A",
  "confidence": "low|medium|high",
  "supporting_claim_ids": ["C-001", "C-004"],
  "falsifier": "什么证据会推翻该判断",
  "review_after": "YYYY-MM-DD",
  "verification": "support|partial_support|falsified|unresolved",
  "verification_receipts": [],
  "review_note": ""
}
```

验证状态：

- `support`：后续一手/强来源与核心方向一致。
- `partial_support`：部分成立，边界或强度被修正。
- `falsified`：出现明确反证。
- `unresolved`：证据不足、时间未到或指标不可观察。

置信度是提出时的主观强度，不等同于验证结果。禁止为了“提高命中率”事后改写原判断；修订应新增 review 记录。

## 5. N/A 规则

以下情况优先 `N/A`：只有发布事实、无价值层变化；部署材料未说明边界；能力仅有厂商宣传；与能源风电的迁移路径需要多个未经验证假设。`N/A` 是合格输出，不是失败。
