# 集团技术雷达（季度）

## 它做什么

参照 Thoughtworks 技术雷达的做法，每季度一期，回答「集团对这项技术的立场是什么」。每个条目放在四个圈之一：

| 圈 | 含义 | 进入条件 |
| --- | --- | --- |
| 采纳 | 集团内已稳定使用，新项目的默认选择 | 必须有集团内生产使用证据 |
| 试用 | 集团内至少一个真实项目在试 | 必须写明哪个项目在试 |
| 评估 | 值得关注，尚无集团内使用证据 | 至少一条证据（信号、主题档案或外部资料） |
| 暂缓 | 新项目不建议使用 | 必须写明原因（安全、合规、成本或有更好的替代） |

象限有四个：模型、工具与平台、方法与流程、风电场景。外部情报站做不了这件事，因为它们没有金风的使用数据。雷达的价值就在这些集团内证据。

## 底线

- **没有证据不上雷达。** 每个条目都要有理由（≤ 80 字）和至少一条证据。放进「采纳」「试用」的条目必须有 `type: internal` 的证据：哪个项目、哪个部门、用到什么程度。
- **集团内证据由用户提供。** 共享中心、AI 平台的使用情况、项目进展，向用户要，或者让用户指定材料；不能凭信号推断「集团在用」。
- **「暂缓」要敢写。** 雷达最有用的部分往往是不该用什么。本期没有「暂缓」条目时 `render` 会提醒，要和用户确认。
- **人定稿。** 本 skill 只做初稿和校验。条目和圈位由用户初审、吕总定稿；`publish` 必须在定稿后、用户确认时才加 `--confirm`。
- **只改自己的字段。** 写首页底座帖时只改 `stance`，读不到或格式不对就停。

## 流程

```bash
S=<本 skill 目录>/scripts; Q=2027Q1
python3 $S/radar.py collect  --quarter $Q --env-file <.env>                  # 本季度信号分布、主题档案判断、上期条目（只读）
python3 $S/radar.py template --material <work_dir>/技术雷达_${Q}_素材.json    # 生成条目模板（沿用上期条目）
#   和用户一起填 <work_dir>/技术雷达_${Q}_条目.json：增删条目、调整圈位、补集团内证据
python3 $S/radar.py render   --material ... --entries ...                     # 校验 + 预览（只写本地）
#   预览给用户初审 → 吕总定稿 → 用户确认后：
python3 $S/radar.py publish  --material ... --entries ... --env-file <.env> --confirm
```

### 起草建议

1. 先看素材里的 `by_topic`、`by_question`、`dossier_judgments`：本季度信号集中在哪些主题，主题档案的判断是什么。
2. 逐条过上期条目：圈位要不要动，理由是否还成立。动了圈位的在 `why` 里写清楚为什么。
3. 新条目只收本季度反复出现、对集团有决策意义的。首期 15–25 条即可，不追求全。
4. 证据写法：
   - `{"type": "internal", "ref": "交付清单智能审核", "note": "供应链部生产使用，覆盖 10452 份清单"}`
   - `{"type": "signal", "ref": "<信号话题 ID>", "note": "一句话"}`
   - `{"type": "dossier", "ref": "智能体与 MCP 安全", "note": "主题档案判断"}`
   - `{"type": "external", "ref": "<URL>", "note": "一句话"}`
5. 条目字段：`name`、`quadrant`、`ring`、`why`、`evidence`；`owner`（集团内负责人或部门）、`url`（站内详情页，例如案例帖）可选。模板里以 `_` 开头的字段只供参考。

`render` 会拦下：圈位或象限不在清单、没有理由或理由超长、含占位符、没有证据、「采纳」「试用」缺集团内证据、条目重名。条数不在 15–25、没有「暂缓」条目时只提醒，不拦。

## 发布做了什么

- 在雷达分类（默认 15，趋势与情报）新建《集团技术雷达｜YYYY 年第 N 季度》：按四个圈分表，列出条目、象限、移动（新、↑、↓、—）、理由和证据；末尾写「本期变化」，包括移出的条目。
- 首页底座帖的 `stance` 字段写入四个圈的条目，每圈最多 8 条，并附雷达帖链接。首页组件 v0.3 读它显示「集团技术雷达」区块。
- `config/radar.json` 的 `history` 追加本期条目，下期据此计算移动。
- 同一季度只能发布一次。修订时直接编辑论坛上那一期雷达帖，并手工同步 `history`。

## 配置

`config/radar.json`：`forum.signal_category_id`（首次使用前必须填，与采集器一致）、`forum.radar_category_id`、`forum.feed_topic_id`（632）、`entries_target`、`quadrants`、`rings`。凭据与 ai-radar-daily 共用 `.env`。
