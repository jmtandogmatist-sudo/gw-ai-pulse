# 【04 今日值得看】的取数规则（截至 2026-11-20）

条数：**5 条**（`render.PICKS_MAX`，2026-11-20 由 4 提到 5；主题组件 .ap-picks 是垂直列表，前端不用改）。

## 一、进池子

`pipeline.update_feed` 每轮重算，取数源是本地信号库 `state/index.sqlite`：

1. `store.recent_signals(now - feed.window_hours)`，`window_hours: 72`；
2. 只留有话题的（`topic_id` 非空——没有帖子就没有可点的地方）；
3. `_in_publish_window`：**发布日期**早于 72 小时窗口的不上首页（防止「今天采到的旧闻」冒充新料）；
4. 按 `radar_rank` 排一次（与 03 雷达同序），后面再按 `_brief_rank` 重排。

## 二、什么算「值得看」（`_is_tool_like`）

判定顺序（2026-11-16 按实测校准）：

1. 命中 `_NOT_PICK` 正则的一律不进——热议/讨论/传闻/据悉/或将/可能/曝光/起诉/诉讼/称/警告/披露/宣布将/联合声明；网信办/国家能源局/发改委/工信部/公示/备案/通知/公告/征求意见/法案/条例/试点/清单；周榜/排名/登顶/市值/股价/财报/营收/辞职/离职/招聘。理由：政策与事件类虽然常含「发布」「上线」，但读者不能上手做什么。
2. `domain == "工具做法"` → 直接通过。
3. 否则**标题必须含工具名词**：开源 / 框架 / 技能包 / SDK / CLI / 插件 / 工具 / 工作流 / 模板 / 基准 / API / 接口 / 驱动 / 内核。
   （「指南 / 方案 / 评估 / 报告」这类故意不算：既可能是教程也可能是分析文，实测「实用指南评估组织 AI 代码蔓延暴露风险」就是分析文。）

## 三、排重与排序

1. **跨块排重（2026-11-20 新增）**：排除已经上了 01 简报与 02 焦点的条目，
   按**信号本体 + 任一来源 URL** 双重排除（不同事件键指向同一篇文章也拦得住）。
   原因是四块原先各自从整池挑，04 四条推荐里曾出现两条正是 01 的二三条。
2. **排序 `_brief_rank`**（与 01/02 同一个函数）：
   - tier：`relevance=3` → 0；`domain` 属于能源AI/政策合规，或命中 Q02/Q05 → 1；其余 → 2；
   - 时效降级：昨天的 +1，前天及更早直接沉到 5（过期层，只在新料不足时兜底）；
   - 次级：可信度 green > yellow > red，再按发布日期，最后按标题保证稳定。
   ⚠️ 注意：04 **没有**按「可上手程度」单独排序，用的是新闻价值序。这是已知的粗糙点。
3. **同站点限额 `feed.picks_max_per_source: 2`**：按**站点**分桶而不是源名
   （IT之家 · AI / IT之家 · 算力 共用 ithome.com 一个额度；DSH 插件生态 / DSH 主仓库 / GitHub Trending 共用 github.com）。
   第一轮严格限 2，凑不满时放宽到 3，仍不够则不限——宁可多一条同源，不让这一块开天窗。

## 四、条数与字段

- 上限 5 条（`PICKS_MAX`）。**是上限不是保证**：池子不够就给几条，0 条时整块不显示（`feed.pop("picks")`），不会拿上一轮的旧内容凑数。
- 每条三个字段：`kind="做法"`、`title`（去掉尾部日期后缀，截 120 字）、`summary`（取摘要首句，截 100 字）、`url`（第一来源 URL）。
- 序号由前端补（`picks.map((p,i) => ({...p, num: pad(i+1)}))`），采集器不写。
- 写进 632 底座帖 JSON 的 `picks` 字段；主题组件渲染成「04 今日值得看」：序号 + 标题（外链，`target=_blank`）+「做法」chip + 摘要。

## 五、与 03 雷达的关系

雷达要完整，精选块才去重。
