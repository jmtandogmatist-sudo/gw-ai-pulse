# 首页各区块重复推荐同一篇文章（2026-11-20）

## 现象

2026-11-20 09:13 的 632 底座帖，同一屏里两处讲同一件事：

| 位置 | 条目 |
|---|---|
| 01 简报第 2 条 | Gemini API 推出 Tool Retrieval 功能预览版（blog.google） |
| 04 今日值得看第 1 条 | 同上，URL 一字不差 |
| 01 简报第 3 条 | 谷歌研究提出自我改进 Harness 架构（ithome.com/1/029/766.htm） |
| 04 今日值得看第 2 条 | 同上 |
| 01 简报第 1 条 | 《中国虚拟电厂发展报告（2026）》解读 |
| 02 右栏「金风 / 能源相关」第 1 条 | 同上 |

即：**04 四条推荐里两条是 01 的复读，02 右栏三条里一条是 01 的复读。**

## 根因

`update_feed` 里四块内容各自独立地从同一个信号池挑：

| 区块 | 取数函数 | 当时是否知道别处用过 |
|---|---|---|
| 01 简报 | `brief_items(sigs, …)` | — |
| 02 焦点 | `focus_lead_item(focus_sig)` | 只排除自己 |
| 02 右栏 | `pick_energy(pool_sigs)`，pool 只去了 focus | 不知道 01 用了什么 |
| 04 值得看 | `pick_items(sigs)` | 完全不知道 |

而且 `brief_items` 只返回**渲染好的文字**（text/url/source），`update_feed` 手里没有
「哪几条已经上了 01」这个信息，想排也无从排起。

## 修法

1. **render**：把「选」和「渲染」拆开——
   - `brief_signals()` 返回选中的 `Signal` 本体；`brief_item()` 只负责渲染一行文字；
     `brief_items()` 保留原语义（内部走这两个）。
   - 新增 `picks_excluding(signals, exclude=[…])`：04 专用，排除名单里的信号，
     **同时按来源 URL 排除**（不同事件键指向同一篇文章也能拦住）。
2. **pipeline**：`update_feed` 先算出 `brief_sigs`，再算出
   `taken_sigs / taken_ids / taken_urls = 01 简报 + 02 焦点`，
   02 右栏与 04 都从 `_not_taken()` 过滤后的池子里挑。
3. 01 与 02 焦点之间原有的互斥（焦点让出 01）保留不变。

## 验证

- `tests/test_picks_dedupe.py` 4 条用例：按信号排除、按 URL 排除、全被占用时返回空、
  仍受 4 条上限约束。全套 `pytest` **261 passed**。
- 632 读回，四块两两求 URL 交集：`01∩02lead 0 / 01∩02energy 0 / 01∩04 0 / 02lead∩02energy 0` 均为 0。

## 遗留 / 设计说明

- **03 雷达仍会包含 01/04 的条目**：雷达是「全量列表」，本来就该完整，
  与精选块的重复是刻意的。若也要去重，会让 `radar_total` 的语义变得含糊，暂不做。
- **同产品不同文章仍可能同时出现**：修后 02 焦点是「Claude Code 增强 MCP 错误提示」，
  04 第 2 条是「Claude Code 支持多平台自动模式（v2.1.328）」，两条是不同发布。
  按产品名去重会误伤这种真实的不同进展，先不引入。
