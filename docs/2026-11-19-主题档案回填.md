# 2026-11-19 主题档案回填：04 主题追踪从「指向信号帖」改成「指向档案帖」

## 1. 问题

首页 04「主题追踪」点进去是 `/t/854` 这种**单条信号**，与 UAT `/t/241` 的**主题档案**（当前判断 / 本周变化 / 观察点 / 近 30 天时间线 / 历史判断）完全不是一回事。

根因：`collector/topics.py::topic_url()` 有档案 id 就用档案帖，没有就退回「该主题最新一条信号帖」；
生产从未建过档案帖（标签 `dossier` 的 `topic_count=0`），四个主题的 `dossier_topic_id` 全为空，
所以 04 的链接全部命中了 fallback。样式层不是原因：组件 11 已启用，生产与 UAT 的组件 CSS 都是 v2（9.5KB）。

## 2. 做了什么（阶段 0）

新增 `01-采集器/scripts/backfill_dossiers.py`，一次性完成三件事：

1. 用 632 现有的 judge/change/next（2026-11-19 13:48 采集器生成）+ 本地索引近 30 天时间线，
   在分类 15 建 4 篇「主题档案｜xxx」（`ais-dossier` 骨架，标签 `dossier`）；
2. id 写入 `state/topic_dossiers.json`（不写 config，保持「运行期代码只读」）；
3. 只改 632 的 `topics[].url`，判断文本不动。

| 主题 | 档案帖 | 本周 +N | 时间线 |
|---|---|---|---|
| 功率预测 AI | [/t/871](https://aicopilot.goldwind.com.cn:3211/t/871) | 2 | 2 条 |
| 国产大模型选型 | [/t/872](https://aicopilot.goldwind.com.cn:3211/t/872) | 13 | 13 条 |
| 智能体与 MCP 安全 | [/t/873](https://aicopilot.goldwind.com.cn:3211/t/873) | 53 | 截断到最新 20 条 |
| 集团 AI 能力上新 | [/t/874](https://aicopilot.goldwind.com.cn:3211/t/874) | 0 | 近 30 天暂无信号 |

导语写明「判断由采集器调用模型生成（非公司结论）」，与 UAT 手写档案的措辞区分开。

## 3. 防回退的小改动

`collector/pipeline.py` 新增 `dossier_ids(cfg)`：`update_feed_topics()` 在写 632 前读
`state/topic_dossiers.json` 并回填 `dossier_topic_id`。

不加这一步的话，周五 17:00 的 `collector topics` 会把 `url` 覆盖回信号帖，档案链接每周失效一次。
测试：`tests/test_topics.py` 里 4 条相关用例（含 extra_tags 合并与人工帖渲染），全量 214 个测试通过。

## 4. 验收（已实测）

- 4 篇档案帖匿名 `/t/<id>.json` 200，`category_id=15`，`tags=['dossier']`，`cooked` 含 `data-wrap="ais-dossier"` 与 `ais-timeline`；
- 档案页加载组件 CSS（`common_theme_11_*.css`），`check_theme_style.py --topic 873` 判定「样式在线」；
- 632 的四个 `topics[].url` 全部指向 871–874（阶段 0 时 `topics_updated_at` 仍是 13:48:17；阶段 1 跑完后为 14:34:06）；
- 标签 `dossier` 的 `topic_count` 从 0 变成 4。

## 5. 阶段 1：档案并入周五周更（2026-11-19 14:34 完成）

`collector/pipeline.py::update_feed_topics()` 现在一次写三样东西：

1. 模型判断（不变）；
2. 4 篇档案帖正文（`render_dossier()`：有 id 更新、无 id 建帖，`external_id=dossier-<tag>` 防重）；
3. 632 的 `topics`（url 用档案 id）。

同一份 judgments，卡片与档案逐字一致——2026-11-19 14:34 回读比对 4/4 全部为 True（judge/change 均相同）。
每次更新把本周判断写进档案 `history`，下周自动成为「历史判断」；上限 `history_limit: 12` 期。
回滚开关：`topics.yaml` 的 `dossiers.enabled: false`，关掉即回到「只更新 632、url 退回信号帖」。

## 6. 采集扩展：带中文标签的内部帖也算「集团 AI 能力上新」

`topics.yaml` 该主题新增 `extra_tags`，周更时 `extra_tag_signals()` 按标签回读 `/tag/<标签>.json`，规则：

- 排除分类 20（信号帖），避免与本地信号索引重复计数；
- 按 `created_at` 换成北京时间、落在 30 天内才收；「本周 +N」按 7 天；
- 跨标签按 topic_id 去重（635 同时带三个标签，只算一次）；
- 标签不存在（404）就跳过，不报错；
- 人工帖在档案时间线里标「（人工帖）」，不打可信度圆点、不写「未审」。

| 标签 | 线上现状（2026-11-19） |
|---|---|
| 集团ai能力上新 | 2 帖：635（11-03）、644（11-04） |
| ai智能体开发平台 | 2 帖：635、789（11-17） |
| 版本更新 | 2 帖：635、413（08-06，超 30 天窗口） |
| 版本迭代 | 1 帖：789 |
| ai探索与应用平台 / ai数字员工共享中心 / 风衍 | 还没有人用，404 跳过 |

实测效果：`集团 AI 能力上新` 从「本周 +0」变成「本周 +1」，`/t/874` 时间线出现 789/644/635 三条
（789 标 ★），`extra_posts=3`。以后有人打新标签自动进来，不用改代码。
