## 3 版面结构（组件 10 的模块用法）

| 位置 | 组件 | 作用 |
|---|---|---|
| 全文外壳 | `[wrap=pu-v12]` | 统一字号、衬线标题、章节条、表格圆角（v1.2 起用它，`pu-article` 是旧壳） |
| 开篇 | `[wrap=pu-lede]` | 一句话说清「这次多了什么、对你有什么用」，替代「各位同事：」的群公告语气 |
| 数字卡 | `[wrap=pu-stats]` + `[wrap=pu-stat]` ×3 | 2 项升级 / 1 版界面重做 / 4 样引用要素 |
| 入口与手册 | `[wrap=pu-note]` | 原文里最容易找不到的两条信息（入口、手册）提到最前面 |
| 总览表 | 原生表格 | 「变了什么 → 一句话 → 谁最该先试」，5 秒决定要不要读下去 |
| 每项升级 | `[wrap=pu-block]` | 把「能看到什么 / 怎么用」收成一块，长文里不散 |
| 场景 | `[wrap=pu-who]` | 带 ✓ 的场景清单，替原文的「① ②」编号 |
| 收获 | `[wrap=pu-tip]` | 每个升级给一句「以前怎样、现在怎样」 |
| 合规提示 | `[wrap=pu-note]` | 来源标注 + 强制性条款以原文为准 + 仅正式员工开放 |
| 行动 | `[wrap=pu-cta]` | 评论区留部门与场景，替原文的「欢迎大家体验，留言」 |

没有用 `[wrap=pu-cover]` / `[wrap=pu-figs]`：本次通知没有配图。若要加图，见第 5 节。

## 4 相对原通知改了什么

| 原通知 | 现在 | 为什么 |
|---|---|---|
| 【喇叭】【冲！】【灵光一现】…表情符号当小标题 | 全部删除，只保留 💡 一处（组件样式里的「一招收获」） | 表情符号在飞书群是分段标记，在长文里会变成噪音 |
| 「① 可联网搜索外部标准，做到有问必答」 | 拆成一节：先讲「库里没有」这个断点，再讲自动联网补齐，并补一句「能找到多少取决于公开网络有没有可检索来源」 | 「有问必答」是承诺，正文里给不出兑现条件时反而扣分；说明边界更像内部技术稿 |
| 「② 忠于标准，原汁原味」 | 改写成「编号 + 名称 + 章节 + 片段 + 一键跳原文」，并解释为什么这四样重要 | 「原汁原味」是形容词，读者记不住；四样东西是可验证的 |
| 「只对正式员工开放」放在小标题括号里 | 提升为独立的合规小节，加粗 | 权限是使用前提，藏在括号里等于没说 |
| 「使用提示」两行 | 独立成「使用提示（重要）」小节，两种来源标注逐条解释 | 这是读者最容易误用 AI 答案的地方，值得单独占一节 |
| 发布方一行 | 保留，并加 `pu-cta` 收口 | 组件样式下没有收口会显得突然结束 |

**没有新增任何数字。** 15 分钟→2 分钟、1 万余项 / 770 项都是 V1.0 上线时公布的口径，稿子里明确标注为「V1.0 上线时的口径」并链回 [topic 538](https://aicopilot.goldwind.com.cn:3211/t/538)；V1.3 本身没有可引用的量化数据，所以不写。
