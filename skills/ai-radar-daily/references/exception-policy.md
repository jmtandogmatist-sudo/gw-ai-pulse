# V3.2 异常与降级策略

原则：内容证据问题 fail closed；非内容型外部依赖可降级但必须留痕；任何降级都不得伪造成功。

| 异常域 | 典型情况 | 阻断/降级 | 必须状态与动作 |
|---|---|---|---|
| 采集缺口 | 搜索服务异常、部分官方源暂不可达、近期日报拉取失败 | 关键官方源或召回复核不完整时阻断 G2；仅非关键扩展源失败可降级 | 记录未访问源、原因、时间和重试入口；不得写 `checked=true` |
| 关键证据 | 空 receipt、数字无原始出处、日期冲突、仅 T4、来源非独立 | 阻断 G1；删除 claim 或整条，不能降级为猜测 | `FAIL/UNRESOLVED`，保存冲突与淘汰原因 |
| 发布状态不确定 | API 超时、响应丢失、状态停在 WRITING/VERIFYING | 阻断重复写；先论坛搜索和回读对账 | `NEEDS_RECONCILIATION`；确认 topic/post 和 SHA 后再决定 |
| 样式与封面 | ImageGen 失败、封面缺失、图片样式不理想 | 可降级：合规历史图或无图引用语；不影响已验证事实 | 标记 `DEGRADED_STYLE`；若模板/脚本要求冲突则重跑自查 |
| 知识库同步 | `enabled=false`、目标未配置、ACL 拒绝、写入或回读失败 | 不删除、不回滚已验证日报；本地 package 必须保留 | `SYNC_PENDING`，记录 manifest、错误和待配置项；不得标 `SYNCED` |
| 飞书推送 | 未获人工确认、连接器不可用、ACL 失败、单群发送失败 | 未确认时阻断；授权后按群独立失败，不重发论坛 | 草稿保留；群级 `FAILED/PENDING`，成功群保持 `SENT` 幂等 |

## 1. 采集缺口

- 重点官方主体未真实访问：G2 FAIL，不得靠媒体替代后伪装官方扫描完成。
- `fetch_recent.py` 失败：手工/只读回读近期论坛可作为替代；若无法完成跨期去重，则阻断发布。
- 周一窗口不足以覆盖周末：补检索后重新召回复核。
- 检索清单损坏：从原始搜索记录重建；无法重建则停止，不从记忆宣称完成。

## 2. 关键证据

- 单一 T0 仅按明确例外保留，并在正文与 receipt 同时标注。
- 关键 claim 失败时不得用模糊措辞逃避证据要求。
- 深度聚焦无法回到官方原始页时删除相关数字或案例；仅剩弱材料时取消该主题。
- 事实层被修改后，判断层、语义复核和脚本自查全部失效并重跑。

## 3. 发布状态不确定

1. 冻结本地待发布正文及 SHA。
2. 记录最后请求时间、动作类型和已知响应，不记录凭据。
3. 只读搜索同刊期主题；若存在，回读首帖并比对 SHA/正文。
4. 已成功则补写状态，不重复创建；未成功且可证明无副作用时，重新请求人工确认后再写。
5. 无法判断时保持 `NEEDS_RECONCILIATION`，交由人工处置。

修订必须从 topic JSON 获取 `post_stream.posts[0].id`。不得把 `topic_id` 推断为 `post_id`。

## 4. 样式与封面

降级顺序：新封面 → 已审核历史封面 → 无图引用语。封面失败不应丢弃正文；但任何资源变更后必须重跑确定性自查。二维码等固定资源缺失且模板要求存在时阻断论坛发布，不能用伪链接替代。

## 5. 知识库同步

- 先生成本地 `knowledge-package/package.json`，集中保存五表结构（Issues / Events / Sources / Judgments / Runs）、最终正文哈希、证据索引及论坛状态；同步时另存 `upsert-plan.json` 和 `sync-result.json`。
- 远端未启用、URL/ID 空或 ACL 未授权：标 `SYNC_PENDING`，列出缺失配置。
- 写入成功但回读失败：仍为 `SYNC_PENDING`，不是 `SYNCED`。
- 同步失败不删除本地正文、论坛帖子、自查报告或 evidence receipts。
- 后续恢复只重试知识库步骤，不重新发布论坛。

## 6. 飞书推送

- 论坛回读未通过、knowledge package 未保存或人工未确认：禁止发送。
- 连接器未授权：保留 JSON/TXT，标明 ACL 阻塞。
- 每群最多按受控策略重试；状态不确定先查消息/幂等记录，不盲重发。
- 多群发送结果彼此独立；一个群失败不得覆盖另一个群的 SENT。
- `record` 操作必须逐群串行，写后回读 JSON。
